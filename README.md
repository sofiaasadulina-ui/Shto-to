# URLGuard — проверка ссылок на вредоносность

Настольное приложение на Python: пользователь вставляет ссылку в окно и получает
оценку риска от 0 до 100 **вместе со списком причин**, по которым программа приняла
такое решение. Проект выполнен для олимпиады по информационной безопасности.

Ключевая идея: вердикт не «чёрный ящик». Каждый балл риска привязан к конкретному
признаку, который можно объяснить и проверить вручную.

---

## Быстрый старт

```bash
pip install -r requirements.txt
python main.py
```

Проверка из командной строки (тот же движок, без окна):

```bash
python -m urlcheck.scoring "http://login.paypal.com.secure-verify.top/signin"
python -m urlcheck.scoring "https://github.com" --network   # с сетевыми проверками
```

Тесты:

```bash
python -m pytest -q
```

## Принцип безопасности

Программа **никогда не открывает проверяемую ссылку** — ни в браузере, ни через
загрузку страницы. Это принципиальное ограничение, а не недоработка:

* по умолчанию проверка полностью **офлайновая**, ни одного пакета в сторону
  подозрительного домена не уходит (за этим следит отдельный тест
  `test_offline_by_default_makes_no_network_calls`);
* при явно включённой галочке «Сетевые проверки» собираются только метаданные:
  DNS-запись, WHOIS, TLS-сертификат и заголовки перенаправлений (метод `HEAD`,
  тело ответа не скачивается);
* все ссылки в отчётах и в интерфейсе показываются в «обезвреженном» виде:
  `hxxp://evil[.]com` — по такой нельзя случайно кликнуть.

## Как считается вердикт

Оценка складывается из трёх независимых источников.

```
                 ┌────────────────────┐
   URL  ────────►│  разбор (normalize)│
                 └─────────┬──────────┘
                           ▼
                 ┌────────────────────┐
                 │ признаки (features)│  34 числовых признака
                 └─────┬────────┬─────┘
             ┌─────────┘        └─────────┐
             ▼                            ▼
     ┌──────────────┐            ┌─────────────────┐
     │  эвристики   │            │   ML-модель     │
     │  19 правил   │            │ TF-IDF + logreg │
     └──────┬───────┘            └────────┬────────┘
            │      ┌──────────────────┐   │
            │      │ сеть (по галочке)│   │
            │      │ DNS/WHOIS/TLS    │   │
            │      └────────┬─────────┘   │
            └───────────────┼─────────────┘
                            ▼
                  ┌───────────────────┐
                  │ агрегация (scoring)│  → 0..100 + уровень
                  └───────────────────┘
```

### Формула агрегации

Эвристики задают базу — это установленные факты о структуре ссылки. ML-модель
может **повысить** оценку (она видит статистику написания, которой нет в правилах),
но лишь **незначительно снижает** её: то, что модель ничего не нашла, не отменяет
уже сработавшего правила. Отсюда несимметричные коэффициенты:

```
если ML ≥ эвристик:   score = эвристики + 0.45 × (ML×100 − эвристики)
иначе:                score = эвристики − 0.20 × (эвристики − ML×100)
score += вклад сетевых проверок (не более +45)
```

Пороги уровней откалиброваны на `data/sample_urls.csv`:

| Балл | Уровень | Цвет |
|------|---------|------|
| 0–29 | Безопасно | зелёный |
| 30–64 | Подозрительно | оранжевый |
| 65–100 | Опасно | красный |

## Эвристики (`urlcheck/heuristics.py`)

| Вес | Признак | Почему это индикатор |
|----:|---------|----------------------|
| 30 | Подмена бренда | Бренд в поддомене или пути, а сам домен чужой: `login.paypal.com.evil.top` |
| 30 | Опечатка бренда (typosquatting) | `paypa1.com`, `arnazon.com` — отличие в 1 символ после снятия маскировки гомоглифами |
| 25 | Символ `@` в адресе | Всё до `@` браузер игнорирует: `sberbank.ru@evil.top` ведёт на `evil.top` |
| 25 | IP вместо домена | Включая обфускацию: `0x7f000001`, `3232235777` |
| 20 | Punycode / смешение алфавитов | Омоглиф-атака: кириллическая «а» вместо латинской |
| 20 | Исполняемый файл в пути | `.exe`, `.scr`, `.apk`, `.hta`, `.vbs` |
| 20 | Вложенный URL в параметрах | Открытый редирект — цель дополнительно проверяется теми же правилами |
| 15 | Слова-приманки | `login`, `verify`, `wallet`, `bonus`, `oplata`, `vhod`… |
| 15 | Сокращатель ссылок | Истинный адрес скрыт |
| 10 | Ввод данных по HTTP | Форма входа без TLS |
| 10 | Зона повышенного риска | `.tk`, `.ml`, `.gq`, `.cf`, `.top`, `.xyz`, `.zip`, `.mov` |
| 10 | Больше 3 поддоменов | Настоящий домен выталкивается за границу видимой части строки |
| 10 | Домен похож на сгенерированный (DGA) | Высокая энтропия **и** почти нет гласных либо много цифр |
| 10 | Кодирование в имени хоста | `%XX` в домене — обход фильтров |
| 5–10 | Аномальная длина адреса | Более 100 / 150 символов |
| 5 | Нестандартный порт | Не 80 и не 443: `:4444`, `:1337` |
| 5 | Много дефисов | `secure-login-update-account.tk` |
| 5 | Двойной слэш в пути | Обход наивных фильтров |
| 5 | HTTP без шифрования | Трафик можно перехватить |

Каждое правило — отдельная функция `rule_*`, каждое покрыто парой тестов
«срабатывает / не срабатывает ложно».

### Гомоглифы

Перед сравнением с брендом имя домена нормализуется: `rn→m`, `vv→w`, `1→l`, `0→o`,
`3→e`, `5→s`. Без этого `arnazon.com` выглядит для алгоритма далёким от `amazon`,
хотя человек эти строки не различает.

## Модель машинного обучения

* **Признаки:** объединение двух ветвей — символьные n-граммы `char_wb` длиной 3–5
  по строке адреса (TF-IDF, до 20 000 признаков) и 34 ручных числовых признака
  из `urlcheck/features.py`.
* **Классификатор:** логистическая регрессия (`class_weight="balanced"`),
  альтернатива — случайный лес (`--algorithm forest`).
* **Зачем n-граммы:** они улавливают написание (`-verify-`, `.tk/`, `xn--`),
  которое не описано ни одним ручным правилом.

Метрики на отложенной выборке 25 % (полный отчёт — `models/metrics.txt`):

| Метрика | Значение |
|---------|---------:|
| Accuracy | 0.986 |
| Precision | 1.000 |
| Recall | 0.971 |
| F1 | 0.985 |
| ROC-AUC | 0.999 |
| **F1 на 5-fold кросс-валидации** | **0.897 ± 0.179** |

Честная оценка — именно кросс-валидация: датасет небольшой (290 ссылок), поэтому
цифры на одной отложенной выборке завышены. Модель — **дополнение** к эвристикам,
а не замена: без неё программа полностью работоспособна.

Переобучение на своём датасете:

```bash
python train_model.py --csv my_dataset.csv --algorithm forest
```

Формат CSV: колонки `url,label`, где `label` = 1 (вредоносная) или 0 (безопасная);
принимаются и текстовые метки (`benign`, `phishing`, `malware`). Подходят публичные
наборы: Kaggle «Malicious URLs dataset», PhishTank (вредоносные) + Tranco (чистые).

### Качество одних только эвристик

На `data/sample_urls.csv`, **с отключённой моделью**:

* **90.4 %** вредоносных ссылок получили уровень выше «Безопасно»;
* **0** безопасных ссылок ошибочно названы «Опасно»;
* 1 из 154 безопасных попала в «Подозрительно».

Оба порога закреплены тестами `test_scoring.py`, чтобы правки правил не ухудшали
качество незаметно.

## Сетевые проверки (по галочке)

| Проверка | Что даёт | Вклад в риск |
|----------|----------|-------------:|
| DNS (`socket.getaddrinfo`) | Существует ли домен | +15, если не резолвится |
| WHOIS (`python-whois`) | Возраст домена | +25 при возрасте < 30 дней, +10 при < 180 |
| TLS (`ssl`) | Валидность и издатель сертификата | +20 при непрохождении проверки |
| Редиректы (`HEAD`, максимум 5) | Куда ведёт цепочка | +15 при уходе на другой домен |

Возраст домена — сильнейший из сетевых индикаторов: подавляющее большинство
фишинговых площадок живёт первые недели после регистрации. Если цепочка
перенаправлений уводит на чужой домен, конечный адрес дополнительно прогоняется
через все эвристики (с половинным весом).

## Интерфейс

* поле ввода + кнопки «Вставить» и «Проверить» (работает и Enter);
* цветной индикатор с баллом риска и полосой прогресса;
* вкладка **Причины** — все сработавшие признаки с весами и объяснениями;
* вкладка **Разбор URL** — схема, хост, раскодированный punycode, домен, поддомены,
  порт, путь, параметры;
* вкладка **Сеть** — DNS, возраст домена, регистратор, TLS, цепочка переходов;
* вкладка **История** — последние 100 проверок из SQLite, клик по строке
  подставляет ссылку обратно в поле ввода;
* кнопка «Скопировать отчёт» — текстовый отчёт в буфер обмена.

Проверка выполняется в фоновом потоке, результат передаётся в интерфейс через
`queue.Queue` и опрос по `after()` — окно не зависает на время WHOIS-запроса.

## Ограничения

Их важно понимать и не выдавать программу за то, чем она не является:

1. **Вердикт вероятностный.** Программа анализирует адрес, а не содержимое
   страницы, — она не заменяет антивирус и не гарантирует безопасность.
2. **Новый вредоносный домен с чистым адресом** (короткий, в зоне `.com`, без
   ключевых слов) эвристиками не ловится. Против этого работает проверка возраста
   домена — но только при включённой сети.
3. **Легитимный сайт может набрать баллы**: длинный адрес с параметром `redirect_url`
   даст «Подозрительно». Поэтому уровни названы «Подозрительно/Опасно», а не
   «Вредоносный», и всегда показан список причин.
4. **Датасет мал** (290 ссылок) и частично составлен по шаблонам, поэтому метрики
   модели оптимистичны. Для реального применения нужен PhishTank/Kaggle.
5. **Списки брендов, TLD и сокращателей конечны** — их нужно поддерживать
   в актуальном состоянии.
